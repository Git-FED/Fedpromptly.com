Founder mission

Write a first-person FedPromptly mission page. Answer: what problem does the founder see, why does building matter, why open source matters, why community matters, and what can a visitor do today? Do not write a resume. Use specific observations, admit what is unfinished, and end with Learn, Build, and Support actions. Mark any personal fact as [CONFIRM].

Project description

Turn these raw project notes into a 100-word project card. Include outcome, current status, who it is for, technologies only when supplied, what is interesting, what is unfinished, and the next action. Never upgrade “concept” into “released.”

Build log

Convert these notes into a dated build log. Preserve failures, decisions, tradeoffs, and next experiments. Include a “what a beginner could copy” section and a “what should not be copied” section. Avoid pretending the result was inevitable.

Launch announcement

Write a launch announcement for FedPromptly using only verified facts. Include the problem, what is available now, one concrete way to participate, and a transparent note about what is still being built. Keep it under 180 words and avoid fake urgency.

Support explanation

Explain what financial support enables for FedPromptly without pressure. Distinguish one-time support, recurring support, and non-financial support. Never promise a product, reward, access level, or tax treatment unless supplied as verified facts.
